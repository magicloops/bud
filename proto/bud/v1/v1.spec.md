# v1

Version 1 Bud daemon-service protobuf schema.

## Files

### `bud.proto`

Defines `BudControl.Connect`, `BudData.Attach`, `BudEnvelope`, traffic/transport enums, typed errors, operation and stream lifecycle enums, reconnect/reconciliation payloads, current terminal/control payloads, data-plane attach/stream payloads, Phase 4.2 proxy-open payloads, Phase 5 proxy-WebSocket payload tags, and a `LegacyJsonPayload` compatibility payload retained for downgrade/fixture support.

Active WebSocket terminal/control payloads and core data-plane lifecycle payloads now use the direct protobuf fields on those payload messages instead of whole-frame `frame_json`. The `frame_json` compatibility field remains on typed payload messages for older fixtures, rollback/downgrade decoding, gRPC adapter transition paths, and proxy/file open-result families that have not yet been moved off the compatibility bridge.

Terminal payloads implement the terminal proto `0.3` cutover (docs/proto.md §6.7): `TerminalReady` (envelope payload field 130) and `AwaitReady` are deleted with their field numbers reserved; `TerminalEvent` (envelope payload field 131) carries the semantic event stream (`session_id`, `event`, JSON `data_json`); `TerminalOutput` drops `seq`; `TerminalEnsure` gains `resume_from_offset`; `TerminalSend` replaces `observe_after_ms`/`wait_for`/`timeout_ms` with `await`; `TerminalSendResult` becomes `dispatched` + JSON `outcome_json` + `error` (readiness/delta/host_cwd reserved); `TerminalObserve` drops wait fields; `TerminalObserveResult` becomes grid-backed (`mode`, `integration`, `alt_screen`, `cursor_row`, `cursor_col`) with the 0.2 readiness/truncated/host_cwd fields reserved; `TerminalInput` drops `await_ready`. Retired 0.2 field numbers are `reserved` rather than reused.

`OperationStatus` and `StreamStatus` carry the daemon journal metadata needed by reconnect reconciliation, including operation type and update timestamps.

`BudData.Attach` is the Phase 3 HTTP/2 data fallback service. The initial implementation uses it for daemon-to-service `terminal_output` while keeping lifecycle, auth, heartbeat, terminal requests, and request-scoped terminal results on `BudControl.Connect`. Phase 4 adds runtime handling for generic `stream_data`, `stream_credit`, `stream_reset`, and `stream_close` frames so proxy/file/local-LLM work can build on bounded data-only streams. Phase 4.2 adds `proxy_open` and `proxy_open_result` typed payload tags for daemon-backed localhost HTTP proxy streams. Phase 4.4 adds `file_open` and `file_open_result` typed payload tags for read-only workspace file stat/read/range streams. Phase 5 adds `localhost_websocket_proxy` plus `proxy_ws_open`, `proxy_ws_open_result`, `proxy_ws_message`, `proxy_ws_close`, and `proxy_ws_error` typed payload tags for message-oriented WebSocket proxying. Phase 7 adds `file_resolve` and `file_resolve_result` typed payload tags for metadata-only absolute POSIX path preflight before service-side file-session creation. Bud-local ds4 adds the `local_llm_http` stream type while `local_llm_open` and `local_llm_open_result` remain transitional JSON-frame payloads.
